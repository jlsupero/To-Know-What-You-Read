# 阅读内容分析报告格式规范

本文档定义 `reading-content-analysis` skill 的标准输出格式。除非用户明确要求其他格式，否则分析报告按以下结构输出。

## 报告结构

### 1. 元信息

置于报告开头，便于定位与归档：

```markdown
- **来源**: 文件名 / URL / 书名
- **类型**: 文章 / 论文 / 书籍章节 / 网页 / 其他
- **主题**: 一句话概括
- **分析时间**: 当前日期
```

### 2. 一句话总结

不超过 50 字，用一句话概括全文核心观点。这是全文最重要的一句话，应能被单独引用。

### 3. 核心论点

- 列出 3-5 个主要论点，每条 1 句。
- 用项目符号组织，按文章的重要性（而非原文顺序）排列。
- 每条论点后可用 `(原文依据)` 标注在文中的位置（章节/段落编号）。

### 4. 论证结构

简述作者的论证组织方式，从以下常见模式中识别（可组合）：

| 模式 | 特征 |
|------|------|
| 问题-方法-结论 | 提出问题 → 介绍方法/方案 → 得出结论 |
| 背景-对比 | 先铺垫背景，再对比不同观点/方案 |
| 时间线 | 按时间顺序叙述发展过程 |
| 金字塔 | 先给结论，再逐层展开论据 |

### 5. 关键论据与数据

- 摘录 3-5 条支撑论点的具体数据、案例或引用。
- 保持原文数据的准确性，不进行换算或改写。
- 每条注明出处位置。

### 6. 关键词

- 5-10 个关键词，按重要性降序排列。
- 每个关键词附 1 句说明（在文中指什么）。
- 用 `主题词` / `方法论词` 标签区分。

### 7. 深度洞察

| 栏目 | 内容要求 |
|------|---------|
| 核心洞察 | 文章最重要的 1-3 个观点/发现，说明其为何重要 |
| 隐含假设 | 作者未言明但构成论证基础的前提 |
| 局限与争议 | 偏见、盲区、数据局限、有争议的结论 |
| 关联与启发 | 与读者知识/现实的联系，以及可执行的行动建议 |

## 输出原则

1. **简洁优先**：不重复原文，只保留信息密度高的内容。
2. **客观中立**：摘要与关键词部分保持客观；个人评价只放在「深度洞察」中。
3. **可溯源**：关键数据与论点标注出处位置。
4. **格式适配**：默认使用 Markdown；若用户要求其他格式（Notion、JSON、纯文本等），按用户要求输出。

## 示例

```markdown
- **来源**: 2024 年某科技评论文章
- **类型**: 文章
- **主题**: AI 工具对知识工作者的影响
- **分析时间**: 2026-08-17

**一句话总结**: AI 工具并未取代知识工作者，而是把工作重心从「执行」转向「验证与决策」。

**核心论点**:
- AI 将常规任务自动化，释放的时间需重新投入更高价值的判断工作。
- 「AI 幻觉」迫使从业者掌握更强的领域知识才能有效校验输出。
- 团队效率差距更多来自工作流设计，而非工具本身。

**论证结构**: 问题-对比-结论（提出效率焦虑 → 对比不同采用方式的团队 → 给出建议）。

**关键论据与数据**:
- 采用 AI 的团队中，常规任务耗时平均下降 40%（第二章）。
- 「AI 幻觉」检出率与从业者领域经验正相关（第三章实验）。

**关键词**:
- 主题词: AI 自动化、知识工作者、AI 幻觉、工作流
- 方法论词: 对比分析、实验研究

**深度洞察**:
- 核心洞察: 真正分水岭是「人机分工设计」，而非是否使用 AI。
- 隐含假设: 作者假设知识工作者有动力重构自身工作方式。
- 局限与争议: 样本局限于科技行业，结论对传统行业推广性存疑。
- 关联与启发: 可立即评估自身重复性任务清单，设计 AI 辅助流程。
```
